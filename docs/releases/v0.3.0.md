# SovereignInterpreter v0.3.0 — Sandbox modes, error envelope, REPL polish

SovereignInterpreter v0.3.0 tightens local execution control and makes REPL feedback readable without changing the sovereign doctrine or the universal safety rule.

## What's new

- **Sandbox modes** — `safe` / `strict` (default) / `full` control Python, shell, and filesystem roots via config and `%sandbox`
- **Error-handling envelope** — typed categories (`PythonError`, `ShellError`, `ModelOutputError`, `SandboxBlocked`, `ExecutionDenied`) render as `[Category] message`
- **REPL UX labels** — `[model]`, `[confirm]`, `[run]`, `[console]`, `[skip]`, `[error]` plus thinking and one-line confirm/run previews
- **Runner cores** — `_run_python` / `_run_shell` centralize execution paths under sandbox policy
- **Config knobs** — `sandbox_mode: strict` and `show_tracebacks: false` in `sovereign.yaml`
- **Filesystem jail alignment** — `safe`/`strict` narrow effective roots to `./workspace`; `full` uses configured `allowed_roots`
- **Shell shortcut gating** — `!command` respects sandbox (blocked unless `full`)
- **Tests** — 61 offline tests covering sandbox matrix, error envelope, and display labels
- **Unchanged doctrine** — universal safety rule, intent detection, `%model`/`%models`, `%reset`, auto-detect, and hallucination-loop prevention remain as in v0.2.0

## Upgrade notes

- Default sandbox is **`strict`**: Python allowed, shell/`!` blocked, FS roots narrowed to `./workspace`
- Use `%sandbox full` (or `sandbox_mode: full`) only when you accept shell + broader roots
- Set `show_tracebacks: true` only when debugging; default stays quiet envelopes
